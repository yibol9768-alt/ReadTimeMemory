## 0. 总论点（论文要证明的一句话）

长对话记忆的瓶颈**不在“存没存下”，而在“读者能不能用上”**。

- 证据 1：100K 上全上下文 74.4 分，但它丢的 25.6 分全是“信息就在上下文里，读者没用上”。
- 证据 2：Hindsight 给读者 125K 字，丢分里读者没用上的占 17.8 分。
- 证据 3：H33 把原文还给读者反而掉 9.7 分；而提炼过的记录在 8K 内就追平 Hindsight。

所以记忆系统的目标应当是：**写入时尽量少丢信息，回答时给读者编译出一份短而对题的视图。**

方法分三层，下层是上层的输入：

```
L2 视图层：按题编译给读者看的视图（选什么粒度、给多少、怎么排）
     ↑ 读
L1 结构层：在账本之上建结构（实体状态和版本、话题时间线、矛盾和更替关系）
     ↑ 读
L0 账本层：只追加、不改写的原子记录，带出处和原话锚点
```

再加一条贯穿各层的约束（来自前两天的漂移发现）：**上层只能从账本重新编译，不能对自己反复改写**，这样记忆不会随时间漂移，1M 规模下仍然成立。

## 2. 怎么“多试”又不“乱试”
- 同一层内同时试 2–3 个变体，都回答这一层的那个问题；比较时只改这一层，下层固定为当前最好的版本。
- 每个变体的预期写在登记里：它应该提升哪种能力、哪种能力不该掉。结果和预期对不上，先查原因，不直接换下一个。
- 一层过了关口才定下来，上层就建在它上面。过不了，回到这一层的错误分析，不往上堆。
- 噪声：用第 2 次独立生成测出的波动定“几分才算数”。在那之前，差距小于 3 分不下结论。

## 3. 论文的形态
- 方法：三层编译式记忆，加上“只从账本编译”的约束。
- 分析：丢分归因（写入、检索、读者）；“给读者更多反而更差”的证据（H33、全上下文、Hindsight）；漂移和不可自检（前两天的发现）。
- 实验：BEAM 100K、1M 和 LongMemEval-S；同一读者、同一判分；每个部件都有消融；方法定型后再跑测试集、多次生成、sol 和开源模型。
- 目标结论：8K 内超过 100K 全上下文；1M 上明显超过 Hindsight；成本在同一量级。
