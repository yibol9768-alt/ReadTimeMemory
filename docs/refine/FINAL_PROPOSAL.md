# Research Proposal：最小命题键——写入时不裁决、读取时成链的对话记忆（CCR）

定稿于 2026-10-16（美东）。经过 3 轮外部审稿，最终 7.2/10，结论 REVISE。本稿已并入第 3 轮审稿提出的协议修正 A–E。

## Problem Anchor
- **根本问题**：在很长的多会话对话里（BEAM 100K/1M、LongMemEval-S，10 万到 100 万 token），让一个固定的 LLM 读者正确回答依赖历史信息的问题，包括抽取、更新、矛盾、时间、排序、摘要等能力。
- **必须解决的瓶颈**：现有做法丢分，主要不是因为信息没存下，而是读者用不上。
  - 100K 上全上下文 74.4 分，丢的 25.6 分全部是“信息就在上下文里，但答案没用上”。
  - Hindsight 给读者 125K 字，丢分里有 17.8 分属于同类。
  - 把原文还给读者（H33）反而掉 9.7 分（p=0.004）。
  - 另一方面，压成 8K 的记录又会丢掉细节和全局脉络：记录检索的丢分里，写入阶段占 15.7 分，信息抽取 70.8 分（逐字检索是 92.0），摘要 39.6 分（全上下文是 53.9）。
  - 召回的“广”和读者的“窄”现在是绑在一起的：要么给多、读者淹没，要么给少、信息缺失。
- **非目标**：
  - 不训练模型；
  - 不追求更大的上下文窗口；
  - 不做新的检索器或向量模型；
  - 不做 agent 式多轮工具调用；
  - 不以 LoCoMo 为主战场（已经饱和）。
- **约束**：
  - 只用 API 模型。实验读者和判分统一用 gpt-6-luna（Pro 代理）；向量用 H20 上的 qwen3-embedding-8b。
  - 开发集：BEAM-100K 120 题、BEAM-1M 40 题、LongMemEval-S 62 题。测试集在方法定型前不碰。
  - 噪声：BEAM-100K 120 题单次生成，95% 区间约 ±5 分。方法比较要做 3 次生成。
  - 目标 ICML 2027，2027-01 下旬截稿。
- **成功条件**：
  1. 在同一读者、同一判分下，读者看到的上下文 ≤8K 字时，BEAM-100K 上超过全上下文（74.4）；
  2. BEAM-1M 上明显超过 Hindsight 和逐字检索；
  3. LongMemEval-S 上方向一致；
  4. 有消融证明提升来自机制本身，而不是来自更多上下文或更多调用。

（论证口径：证据覆盖与读者可用性之间的取舍。全上下文的丢分按定义全记为读者损失，不作为“读者过载”的独立证据。）

## Technical Gap
- 对话里同一个命题会被多次陈述：更新、改口、前后矛盾。BEAM 专门考这一点。
- **不加结构的做法**（逐字检索、记录检索、Hindsight 事实）：同一命题的说法分散，召回不全，读者看不出它们是同一件事。
  - 诊断（记录检索，BEAM-100K 开发集，矛盾题 12 道、共 42 个评分点）：
    - 写入时一边没被写下：10 个评分点；
    - 两边都在、读者自行裁决：10 个评分点。
  - 事件排序题有 12 个评分点丢在召回。
- **写入时判定有效性的做法**（TRACE、Graphiti、Mem0）：要建图，要在写入时判定取代关系。这种判定有时不可靠，或者对回答并不必要。这是一个待检验的假设，不是断言。

## Method Thesis
写入时只给每条说法挂上它所属的“可变命题”键，永不判定有效性；读取时按键闭包，以完整链为单位打包，把裁决留给读者。

## Contribution Focus
- **主贡献**：受限接口的充分性。在固定读者预算下，“命题身份 + 同命题说法共同入选”这一个结构，对目标任务已经足够，不需要持久的有效性判定。
  - 最终主张由 A/B/C 的结果决定：
    - 收益来自闭包补全，而成链呈现不额外加分：主张收缩为“命题闭包召回”；
    - C 在同一批记录上稳定优于 B：主张包括呈现方式。
- **辅助**：同一账本上，受控比较不加结构、写入时有效性标注、读取时裁决、通用压缩四种做法。
- **不是贡献**：账本、出处、多路检索、时间图、按时间排序本身。

## Proposed Method
### 写入
- 在现有 Lychee-lite 编码提示上加两条：
  1. 给每条记录分配 slot：复用候选表中的 id，或新建 id 并写一句规范化的命题陈述。
     - 陈述只写“问题”（实体、属性、必要时写明是哪一次事件），不写当前答案。
     - 两次不同的 Foot Locker 之行是两个 slot；同一次计划的改期是一个 slot。
  2. 不判断哪个说法正确；与先前不一致的说法两边都写成记录。
- **候选表**：按本段文本与 slot 陈述的向量相似度取 top 20，加上最近使用的 10 个，去重。
- 一条记录最多挂 2 个 slot；更多独立命题时拆成多条记录。
- 实体消歧沿用现有消歧状态，与真假判定分开。

### 读取
1. 规划和种子召回同记录检索。
2. 按种子排名依次取 slot；每个 slot 取账本全链。
3. **打包**：
   - 链按 slot 首次出现的种子排名排序；能完整放进剩余预算的链才收，否则跳过、继续下一条，并记录被跳过的链；
   - 链内按说话时间、来源轮次排序；
   - 每条标说话日期、事件日期（只在原话明说时标）、说话人、来源 id；
   - 所有元数据都计入 8K 预算；
   - 挂两个已收 slot 的记录只出现一次。
4. **补散条**：剩余预算按原排名补“无 slot 或单条 slot”的记录。被跳过的多条链里的记录不作为散条补回，避免混出半条链。
5. **读者**：所有条件用同一个提示。
- **有条件的保证**：每个被收入的 slot，其账本全部记录都在上下文中。完整链和散条分开统计、分开报告覆盖率。

## Validation（同一冻结账本、同一规划、同一种子排名、同一读者提示）
| 条件 | 内容 | 用来回答 |
|---|---|---|
| A | 种子平铺（记录检索） | 基线 |
| B | 闭包平铺：A 加闭包补全的记录，按排名平铺；闭包新增的记录排在其所属 slot 的种子之后 | B−A：补回证据 |
| C | CCR：与 B 相同的记录 id，按链呈现 | C−B：呈现方式 |
| D | 有效性标注：与 C 相同的记录和链，每条加写入时标签（当前有效 / 已被取代 / 与某条矛盾未决 / 证据不足） | C−D：持久有效性判定的作用 |
| E | 只留最新（有损消融，可选） | 下界 |
| F | 通用压缩 RTC：输入为 B 的扩展集，带同样的元数据 | C−F：结构 vs 通用压缩，并比较 token |

- **D 的标签**：在线判定，只看到当时为止的前缀，不看到问题；允许“矛盾未决”和“证据不足”，不强制判取代。D 的分类错误要单独审计，结论只限于“持久有效性标注”这一点，不外推到 TRACE、Graphiti 整个系统。
- **同记录集对齐**：B、C、D 共用同一组记录 id。选记录集时按 D 的序列化长度（最长）留足预算，保证三者都不超过 8K。
- **统计**：3 次生成，按对话聚类的配对检验。“不差于”的非劣界限定为 3 分，用配对置信区间判断，不显著不等于等价。报告每题输入、输出 token 和写入时候选表的额外 token。
- **继续规则（唯一）**：
  - 第 1 次生成只作实现核对；
  - 是否继续，看 3 次生成平均：C−A ≥ +3，并且矛盾类或知识更新类至少一类上升，就继续；否则放弃 CCR，回到方法树。
- **最终成功**：四项锚点成功条件全部报告；投稿层级根据留出集和机制证据决定，不根据开发集门槛决定。
- **slot 审计**：
  - 漏并：矛盾和知识更新题的两边是否同 slot，24 题；
  - 误并：50 个最大的 slot，作为高风险子集单独报告。

## 风险与投稿层级（审稿人的判断，照录）
- 若开发集只是小幅正结果：更可能是强 workshop，或者实证、分析型论文。
- 方法型 ICML 正刊仍然可能，但需要三件事：方法冻结后在留出集上达到锚点；对照揭示一个有分量、非显然的原则（例如“只需命题身份，不需有效性”）；有效率优势。
- 不为凑贡献而加结构。

## 时间线
- 10-16：slot 编码（6 段，约 300 次调用），slot 审计，A/B/C 实现核对；
- 10-17：A/B/C/D/F 3 次生成；
- 10-18：BEAM-1M、LongMemEval-S。
