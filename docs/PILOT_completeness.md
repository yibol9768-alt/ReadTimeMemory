# 小试方案：话题线完整索引（Complete Thread Index），2026-10-23 草案

## 1. 要检验的假设
H-C：对需要看全证据的问题（排序、汇总、多会话、最新值/变化、判空），用增量维护、完整的话题线索引替代前 k 检索，能显著提高“证据召回”，进而提高答题分；这一优势随对话变长而变大（1M > 100K）。

非参数化：不训练任何模型；索引只由已有记录的元数据和嵌入增量构建；记录本身只追加、不改写。

## 2. 方法（小试版）
写入侧（从已有记录增量构建，不重新编码）：
1. 每条记录已有 `topic`、`entities`、`time`、`sources`。对 `topic` 做嵌入（H20 qwen3-embedding-8b，免费）。
2. 话题线 = 在线聚类：按时间顺序逐条加入记录；与现有话题线标签的余弦相似度 ≥ τ 则并入，否则新开一条。τ 在开发集上用少量人工检查定一次，之后冻结。
3. 每条话题线保存：标签（成员 topic 的代表）、按时间排序的全部记录 id（倒排表）、首末时间、所涉会话。实体同理建实体倒排表。
4. 增量性：新记录只追加到某条线的末尾，不重排、不重写已有内容。

读取侧：
1. 题型：复用已冻结的点/面路由（route.json）。点状题照旧走现方法（note3_deep），不变。
2. 面状题：
   a. 选线：用问题嵌入取前 m 条候选话题线（m=20），再由读者模型一次调用从候选标签里选出相关的线（可多选）。
   b. 取全：取出所选话题线的全部记录，按时间排序；超过预算时按会话做“逐会话压缩”（每个会话一段，保留时间和关键数值），而不是按相似度截断。
   c. 交给现方法的编译 + 作答（笔记仍然五段），只是证据来源从前 k 换成完整话题线（并保留原 6 万字检索作补充，消融里分开）。

## 3. 对照组（全部在同一读者、同一提示下）
- A0 现方法 note3_deep（6 万字前 k 检索 + 编译）——已有 luna 结果可直接复用。
- A1 A0 + 完整话题线（本方法）。
- A2 只给完整话题线，不给前 k 检索（看话题线本身够不够）。
- A3 预算对齐：A0 但检索预算加到与 A1 相同字数（排除“只是给得更多”）。
- A4 话题线换成随机同长度记录（排除“只是多了内容”）——可选。

## 4. 评测
阶段 0（机制指标，先做，几乎不花钱）：证据召回
- 对 1M 和 100K 开发集的面状题，把每个评分要点拿去问判分模型：“这条要点需要的信息在给定证据里吗？”（复用 mem/erran.py 的判定提示）。
- 比较 A0 的 6 万字检索证据 vs A1 的完整话题线：召回率（要点被覆盖的比例）。
- 判定用两个不同家族的模型：DeepSeek-V4.1-Flash（H20）和 Qwen3.8-27B（H20），报告两者一致率；不用 luna（避免自判）。
- 通过标准：A1 召回比 A0 高 ≥10 个百分点（1M），两个判定模型方向一致。

阶段 1（答题，阶段 0 通过才做）：
- 读者：DeepSeek-V4.1-Flash（H20，免费），另用 luna（Plus，少量）跑 1 次做对照。
- 判分：luna（与以往可比）+ Qwen（独立家族）两套，报告一致率。
- 题目：1M 开发集面状题（37 题）+ 100K 开发集面状题（72 题）；3 次生成。
- 通过标准：1M 面状题 A1 − A0 ≥ +3 且 A1 − A3 ≥ +2（预算对齐后仍有优势），两个判分模型方向一致；点状题不受影响（不走新路径）。
- 统计：按对话聚类 bootstrap，报告区间。

## 5. 停止条件（任一触发即停，汇报讨论）
- 阶段 0 召回提升 < 5 个百分点，或两判定模型不一致。
- 阶段 1 A1 − A3 ≤ 0（优势只是预算带来的）。
- 查新发现增量完整索引 + 1M 规模的同类方法。

## 8. 风险
- 话题线切得太碎或太粗：τ 的选择会影响结果 → 阶段 0 同时报告 2–3 个 τ 的召回曲线，选定后冻结。
- “写入时就没记下”的信息索引补不回来（1M 开发集约 12 分）。
- 面状题样本小（1M 37 题）→ 结论以 1M+100K 合并和区间为准，不看单个能力。

评分（ICML 1–10）：新颖性潜力 4；“是方法而非工程技巧” 3.5；小试能否检验假设 4.5；替代解释排除 4；做成后上限 5.5。建议：**改了再做**。
- 查新：未见“增量完整索引 + 穷举型题保证完整 + 不训练 + 1M 评测”，但周围很挤。最接近：QGMem（2610.11920，10-08，事件索引原子单元 + 合并成保留状态轨迹的“记忆线”；我已核实摘要，评审称其在 BEAM 1M/10M 评测、事件排序用 Kendall τ、检索 top-k、图编码需训练——这几点摘要页未写，待读全文确认）https://arxiv.org/abs/2610.11920 ；TraceMem（2602.09712）主题→小节→线程；Entity-Memory Graph Retrieval（2608.27925）；MemForest（2605.23986）增量时间层级索引；Scroll（2608.21690）代码直接扫只追加日志。
- 主要问题与改法：
  1. 阶段 0 必然通过（A1 = A0 + 话题线，证据只增不减）→ 改为同字数召回、召回–字数曲线，并报精确率。
  2. 缺最关键对照：用免费 DeepSeek 对每条记录判“与题相关吗”的**全量扫描**（完整性上界）；另加 Hindsight observations、QGMem 式线内 top-k。主张应是“以全扫一小部分的成本接近全扫的完整性”。
  3. 方法缺自身优势（τ、选线、压缩都会悄悄漏证据）→ 把完整性做成可检查的性质：索引对记录库覆盖率可测（以全扫为参照）；选线高召回（标签 + 实体倒排 + BM25 并集，读者剔除）；判空给“查过哪些线”的凭证；计数/最新/之前/排序/判空用确定性操作，LLM 只逐条抽取；给出“正确率 ≥ 索引召回 × 抽取准确率”的简单界。
  4. 样本小（1M 37 题，+3 在约 ±8 的区间内）→ 加 LongMemEval-S 多会话计数题（约 133 道）、BEAM 10M；逐题配对检验，事先写判定规则；机制指标（计数是否精确、判空是否正确）确定性判分；事件排序用 Kendall τ，摘要题不混入穷举型。
  5. 判定与路由偏差：长证据上的“在不在”判定要人工抽 50 条核对；路由错误损失单独报；写入缺失约 12 分是天花板需说明；长度趋势至少加 10M。
- 评审给的顺序：先花一天用 DeepSeek 跑全量扫描上界 + 同字数召回；全扫相对 A0 提升 < 5 个百分点就停；有空间再改成“可核查的完整性”方法；11 月中旬前在预算对齐对照下拿不到优势就回保底方案。
