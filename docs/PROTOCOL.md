## 1. 流程
调研 → 复现基线（只用 luna，只跑子集）→ 基线错误分析 → 总结方法方向 → 在基线上加方法，每个部件都做消融 → 迭代 → 方法定型后才跑测试集、多次生成、sol 等其他模型。
每个新想法先在 `PROGRESS.md` 的假设总账里登记：假设、成功标准、用哪个切分，然后才跑。

## 3. 指标与判分
- **主指标：** 各数据集的官方问答指标。
  - BEAM：官方判分提示（`mem/beam_judge_prompt.txt`），每个评分点 0/0.5/1，按题平均，再按 10 种能力报告。
  - LongMemEval：官方判分提示。
  - LoCoMo：沿用 `locomo_exp.JUDGE_SYS`，类别 1–4，不含对抗题。
- **判分模型统一用 luna**（gpt-6-luna，effort=low），所有方法都一样。
- 账本考题、时间平均保留都只作**诊断指标**，不能单独作为方法有效的证据。

## 4. 对照的统一条件（参照 MemDelta 的教训）
- 同一个读者模型：复现和方法开发阶段一律用 gpt-6-luna（Pro，18318）。
- 同一个判分模型、同一套判分提示。
- 向量模型：复现时先用各方法论文或仓库的默认设置（忠实复现），并记录下来；做方法对比时再统一到同一个向量模型做对照。
- 上下文预算：报告每个方法回答时实际给读者看的 token 或字符数。
- 写入成本：按实际调用记录的输入、输出 token 统计（`llm.py` 的缓存记录里有）。

## 5. 子集大小与统计
- 复现阶段（只看能否复现到“合理水平”，相对排序接近论文）：
  - BEAM-100K 开发集 120 题；
  - LongMemEval-S 开发子集 60 题；
  - LoCoMo 每段抽 50 题，共 300 题。
- 方法比较：同一题配对，报符号检验和按对话的自助法区间。
- 方法定型后：每个配置独立生成 3 次，按“题目 × 生成次数”做层级检验。

## 6. 记录
- 每个实验在 `runs/<实验名>/<模型>/` 下有原始结果，对应脚本在 `runs/*.sh`。
- `PROGRESS.md` 写结论（包括失败的）；`SURVEY.md` 写调研；`docs/reports/` 写日报和周报。
- 写进度前先查美东时间（`TZ=America/New_York date`）。
