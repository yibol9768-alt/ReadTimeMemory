## 2. 论文要讲的故事（如果方法成立）

**一句话：** LLM agent 的记忆在每次改写时都会悄悄遗忘，而且它自己检查不出来；用不可改的原始记录出题来考它、只修补考砸的部分，可以用远低于整本重建的成本把遗忘挡住。

暂定标题：*Memories Can't Audit Themselves: Ledger-Grounded Testing Against Drift in LLM Agent Memory*

**贡献（按审稿人会看的顺序）：**
1. **现象（测量）：** 第一个系统测出 LLM 自改写记忆的遗忘曲线。它和改写次数、记忆预算、事实类型、模型强弱的关系，在 3 个数据集、≥3 个模型上都成立。
2. **不可自检（分析）：** 证明并实测“从记忆本身出题”的检测率有上界：丢掉的事实不可能被出成题。这解释了为什么 MemDream 一类自探测方法挡不住漂移，它们自己的附录也显示罕见事实 20 轮后掉 12–13%。
3. **方法：** 测试驱动的记忆维护（暂名 LedgerTest / TDM）。
   - 写入时把每个事实连同来源记进不可改账本。
   - 维护时按调度从账本抽题考当前记忆，考砸的定向修补。
   - 调度用间隔重复（Leitner）：考过的隔久点再考，考砸的勤考。
   - 可选：考题本身做检索键；只在汇总题考砸时写汇总记录。
4. **理论：** 一个简单的“遗忘—修补”马尔可夫模型。每次改写每条事实以概率 p 丢失，每期抽 K 题，修补成功率 s，可以推出稳态保留率和达到目标保留率所需的最小 K，并说明间隔调度在什么条件下优于均匀抽题。用实测的 p 验证预测曲线。
5. **成本—效果：** 在同一张帕累托图上比较整本重建（贵、准）、滚动改写（便宜、忘）、RAG、Lychee、MemDream 式自探测和我们的方法。

**为什么这能到 ICML：** 有现象、有反直觉的分析（自检不可能）、有方法、有理论、有大规模多模型实验和成本分析。不是只调提示词。

## 4. 实验矩阵（正文要有的）

**数据集**
- LoCoMo：10 段对话，每段约 19–32 个会话，用“早期事实题”测漂移。
- BEAM：100K 档 20 段，500K 档抽 5 段；只用其中能测保留率的题：信息抽取、知识更新、时间、多会话。
- LongMemEval-S：抽 100 题。每题历史各不相同，成本高，只做主表一行。

**模型**（受资源约束）
- 主跑：Pro gpt-6-luna。
- 复核：Pro gpt-6.1-sol（强）。
- 开源：DeepSeek-v4.1-flash（H20，全局 2 并发，慢，只跑主表）和 Qwen3.8-27B（H20 上有，需要和用户确认能不能用）。

**记忆架构**（方法要证明是“插件”，不绑一种记忆）
1. 滚动摘要（MemGPT 式核心记忆，我们现在的 roll）；
2. 结构化记录 + 合并（Lychee 式，合并时也会丢）；
3. Mem0 式增删改（开源实现）。

**条件**
- 整本重建（上界）、滚动改写（下界）、重读（restudy）、自探测（MemDream 式）、账本测试（ours）。
- 我们方法的消融：去掉间隔调度、去掉定向修补（改成重读）、K = 4/12/24、检查间隔 1/3/6、修补提示词。

**指标**
- 早期事实保留率、各类题正确率（官方判分）、每会话 token 成本、维护调用数。
- 配对检验加 bootstrap 置信区间；每格 ≥ 50 题；3 个随机种子（抽题种子）。

**规模估计**
主表约 3 数据集 × 3 模型 × 6 条件，加消融，约 3–4 万次调用。Pro 额度不够全跑，所以：
- Pro 跑主模型的全部；
- sol 只跑主表；
- 开源模型只跑 LoCoMo 和 BEAM-100K。
需要和用户确认点数预算（见第 8 节）。

## 7. 主要风险和对策

| 风险 | 对策 |
|---|---|
| 方法提升不显著（G1 不过） | 先诊断：是检测不准（判分器）还是修补不进去（改写时又丢了）。修补可以改成“写进单独的保护区”而不是塞进改写提示词。仍不行就转 B 线 |
| 审稿人说“就是加了提示词” | 理论小节加上可插拔到三种记忆架构，加上和“重读”的对照（证明不是多看一遍的效果），加上调度消融 |
| 判分器偏差（同一模型自己判自己） | 主表换判分模型复核（sol 或 DeepSeek），人工核对 100 条，报告一致率 |
| MemDream 复现不公平 | 按其论文描述实现无训练版，明确标注；同时把“从记忆出题”的不可能性写成可证明的性质，不完全依赖复现数字 |
| 资源不够（Pro 额度、DeepSeek 2 并发） | 主模型优先；开源模型只跑主表；尽量用缓存复用（同一改写前缀共享）；需要时请用户批点数 |
| 有人先发同样的东西 | 每两周查一次新（arXiv 关键词：self-testing / rehearsal / drift / consolidation + memory），先挂 arXiv 占位（G3 后） |
