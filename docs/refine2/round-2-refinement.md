# Round 2 Refinement（方向调整：受控拆解 + 低上下文方法）

写于 2026-10-16 21:30 美东。本轮不是对 CTR 的小修，而是根据第 1 轮审稿和此后 10 个小试的结果，改变论文的主张。所有数字为我们自己在同一读者（gpt-6-luna）、BEAM 官方评分提示判分下跑出；开发集；测试集未动。

## Problem Anchor（与 round 0 原样相同）
- **根本问题**：很长的多会话对话（10 万到 100 万 token），一个固定的 LLM 读者要回答依赖历史的问题。问题类型既有“点”（某个值、某次计划、有没有说过），也有“面”（某个主题这几个月按什么顺序发展、整个过程的总结）。
- **必须解决的瓶颈**：每种现有记忆只用一种分辨率存和给（详见 round 0）。覆盖范围和细节分辨率被同一个预算绑死。
- **非目标**：不训练；不做更长上下文；不做新的向量模型；不做多轮 agent 工具调用；不以 LoCoMo 为主战场。
- **约束**：只用 API 模型；读者、编译、判分都用 gpt-6-luna；向量 qwen3-embedding-8b；目标 ICML 2027。
- **成功条件**：1M 上明显超过 Hindsight 且上下文 ≤ 其 1/2；100K 不低于全上下文；LongMemEval-S 方向一致；消融证明增益来自机制。

## Anchor Check
- 成功条件 1 只部分满足：上下文约 1/5，但准确率是“持平略高”，不是“明显超过”。条件 2 点估计满足（72.3 vs 69.9，区间跨 0）。
- 我们据此调整主张：不再声称新的记忆表示更好，而是声称（a）一个受控拆解说明公开分数差异的来源，（b）在拆解给出的“真正起作用的因素”上构造的低上下文方法。
- 这是主张的收窄，不是问题的漂移：瓶颈仍是“覆盖 vs 读者可用性”，只是证据显示决定因素在读者侧和预算侧，而不在表示。

## Revised Proposal

### Title（暂定）
记忆系统的分数从哪里来：BEAM 上的受控拆解，以及一个用 1/5 上下文达到同等水平的读取策略

### Thesis
- 在长对话记忆基准上，系统之间的公开差距主要来自读者侧的因素（答题提示、读者是否被引导去扫描和交叉比对）和召回预算，而不是记忆的存储表示。在同一读者、同一判分、同一提示下，Hindsight 的叙述式事实与原子记录在相同预算下不可区分。
- 依据这一点构造的读取策略：按题面区分点 / 面，点状题给短的记录视图并做读取时冲突检查，面状题给较深的记录召回；在两个规模上达到或略超 Hindsight + 冲突检查，读者上下文约 1/5。

### Contribution Focus
- **主贡献（分析）**：BEAM 100K 与 1M 上的受控拆解，按因素报告分数变化：读者答题提示、召回预算、存储表示、读取时冲突检查、“先写笔记再答”。每个因素在固定其他因素下测量，3 次生成，按对话聚类区间。
- **次贡献（方法）**：点 / 面路由的预算分配读取策略，在公平比较下与最强开源系统持平或略高，读者上下文约 1/5。
- **不是贡献**：冲突检查（RAG 已有）、原子记录（LycheeMemory）、点 / 面路由的调用形式（Adaptive-RAG 类）。

### 必须补的证据
1. 第二套读者模型（例如 H20 上的开源模型，或 sol），检验拆解的结论是否跨读者成立。
2. 判分模型换一个（同一批回答），检验排名是否随判分变化。
3. LongMemEval-S（62 题开发集）上同样的提示、预算、表示三项对照。
4. 写入成本统一计量（Hindsight retain 的 token 尚未计）。
5. 测试集：方法和对照冻结后各跑一次。

### 风险
- 分析型主贡献在 ICML 正刊不一定被接受；可能需要把方法部分做强，或投更适合分析的赛道。
- 读者只有 luna 一个家族时，结论可能是 luna 特有的。
